# WHOO mobile project instructions

- Start each requested change with a concise numbered checklist of the user's relevant requirements. Keep it concrete so the user can spot omissions. Continue authorized work without making the checklist an approval gate.
- Inspect the supplied mockups before editing. Treat their layout, asset orientation, spacing, background treatment and logo placement as specifications; do not substitute a new composition.
- This project is mobile only. Preserve the approved card artwork and intro compositions unless the user explicitly changes them.
- Background colour belongs at the top and fades into the normal dark app base around halfway down the viewport. Do not stretch a coloured wash down a long page. Panels stay translucent and headers share the page background.
- Keep mobile screens compact. Avoid repeated navigation buttons when the bottom navigation already provides the destination.
- The current delivery is an interactive HTML prototype. Clearly distinguish sample financial/recovery interactions from live backend integrations.
